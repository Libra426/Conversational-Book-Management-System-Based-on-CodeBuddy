# 需求规格说明书

## 1. 项目目标

开发一个支持读者管理、借阅证管理、图书借还、借阅查询、图书预约、系统维护与超期罚款的图书管理系统。

## 2. 参与者

| 参与者 | 说明 |
|---|---|
| Reader 读者 | 查询图书、查询本人借阅信息、预约图书 |
| Student / Teacher | Reader 的子类型，拥有不同借阅规则 |
| Librarian 图书管理员 | 代理读者办理借书、还书，查询任意读者借阅信息 |
| SystemAdmin 系统管理员 | 维护借阅证、图书标题、馆藏副本、管理员、借阅规则与罚款规则 |

## 3. 功能需求

| 编号 | 功能 | 验收标准 |
|---|---|---|
| FR-001 | 注册读者账号 | 传入姓名/院系/读者类型/邮箱/电话，系统创建 Reader 并返回唯一 id |
| FR-002 | 办理借阅证 | 系统管理员可为已存在读者生成唯一 card_no，同一读者仅一个有效证 |
| FR-003 | 删除借阅证 | 系统管理员可注销借阅证（状态置为 CANCELLED） |
| FR-004 | 添加管理员 | 系统管理员可新增图书管理员或系统管理员 |
| FR-005 | 删除管理员 | 系统管理员可删除图书管理员或系统管理员 |
| FR-006 | 添加图书标题信息 | 系统管理员可新增 BookTitle（书名/作者/ISBN/出版社/类型） |
| FR-007 | 删除图书标题信息 | 系统管理员可删除 BookTitle |
| FR-008 | 添加馆藏副本 | 系统管理员可为标题新增 LibraryItem（唯一条码） |
| FR-009 | 删除馆藏副本 | 系统管理员可移除 LibraryItem（状态置 REMOVED） |
| FR-010 | 查询图书 | 读者可按书名/作者/ISBN 查询 |
| FR-011 | 借阅图书 | 图书管理员输入借阅证号与条码，通过全部校验后创建 Loan |
| FR-012 | 归还图书 | 图书管理员输入条码，更新 Loan 与副本状态，超期则生成罚单 |
| FR-013 | 查询借阅信息 | 读者查本人、图书管理员查任意读者的当前/历史/超期借阅 |
| FR-014 | 预约图书 | 读者对标题预约，按时间排队，禁止重复预约 |
| FR-015 | 计算超期罚款 | 按超期天数 × 借出物类型日罚款额计算 |
| FR-016 | 维护借阅规则和罚款规则 | 系统管理员可新增/更新 borrow_policies 与 fine_rules（upsert） |

## 4. 业务规则

| 编号 | 规则 |
|---|---|
| BR-001 | 借书、还书必须由图书管理员代理完成 |
| BR-002 | 借阅证号格式 `CARD`+4位年份+6位序号，全局唯一 |
| BR-003 | 同一读者最多一个有效借阅证 |
| BR-004 | 借书前必须验证借阅证存在且有效 |
| BR-005 | 借书前检查当前未还数量不超过读者类型上限 |
| BR-006 | 借书前检查无超期未还图书 |
| BR-007 | 借书前检查馆藏副本存在且状态为 AVAILABLE |
| BR-008 | 借阅期限按读者类型确定 |
| BR-009 | 还书时若超期，按借出物类型日罚款额生成罚单 |
| BR-010 | 超期天数 = return_date - due_date，<= 0 时不罚款 |
| BR-011 | 同一读者对同一标题仅一个有效预约，预约按 created_at 排队 |
| BR-012 | 读者、图书管理员、系统管理员权限互斥 |
| BR-013 | 馆藏副本条码全局唯一 |

## 5. 非功能需求

- **NFR-001 分层**：采用 presentation / application / domain / infrastructure 分层，业务规则不入 Controller。
- **NFR-002 可测试**：核心用例（借书、还书、预约、罚款、权限失败）均有自动化测试。
- **NFR-003 可维护**：借阅规则与罚款规则数据驱动（策略表），可配置、可替换。
- **NFR-004 可追踪**：Specs 与代码纳入 Git，Agent 使用记录完整。

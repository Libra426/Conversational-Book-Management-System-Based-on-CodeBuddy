## 3. 重点用例详述

### UC-101 办理借书

- 主要参与者：Librarian
- 前置条件：图书管理员已登录；读者已有有效借阅证；馆藏副本存在。
- 后置条件：创建 Loan，副本状态置 BORROWED。
- 基本事件流：
  1. 图书管理员输入借阅证号与馆藏条码。
  2. 系统验证借阅证存在且有效。
  3. 系统检查读者当前未还数量是否超过其类型上限。
  4. 系统检查读者是否有超期未还图书。
  5. 系统验证馆藏副本存在且状态为 AVAILABLE。
  6. 系统创建借阅记录 Loan，根据读者类型计算 dueDate。
  7. 系统更新副本状态为 BORROWED。
- 备选事件流：
  - 3a 超过借阅数量 → 拒绝借书，提示“超出借阅数量”。
  - 4a 存在超期未还 → 拒绝借书，提示“存在超期未还图书”。
- 异常事件流：
  - 2a 借阅证不存在或已注销 → 拒绝，提示“借阅证无效”。
  - 5a 副本不存在 → 拒绝，提示“非本馆藏书”。
  - 5b 副本不可借（BORROWED/RESERVED/REMOVED）→ 拒绝，提示“图书不可借”。
- 关联需求：FR-011、BR-004/005/006/007/008。

### UC-102 办理还书

- 主要参与者：Librarian
- 前置条件：存在未归还的借阅记录。
- 后置条件：Loan 置 RETURNED，副本置 AVAILABLE，超期则生成 FineRecord。
- 基本事件流：
  1. 图书管理员输入馆藏条码。
  2. 系统验证副本存在。
  3. 系统查找该副本未归还的 Loan。
  4. 系统设置 returnDate，Loan 状态置 RETURNED。
  5. 系统更新副本状态为 AVAILABLE。
  6. 若超期，系统按借出物类型计算罚款并生成罚单。
- 异常事件流：
  - 2a 副本不存在 → 拒绝，提示“非本馆藏书”。
  - 3a 未找到借阅记录 → 拒绝，提示“未找到借阅记录”。
- 关联需求：FR-012、BR-009/010。

### UC-004 预约图书

- 主要参与者：Reader
- 前置条件：读者已注册；标题存在。
- 后置条件：创建 Reservation，状态 ACTIVE，按 created_at 排队。
- 基本事件流：
  1. 读者提交标题编号。
  2. 系统验证读者存在。
  3. 系统验证标题存在。
  4. 系统检查该读者对该标题无有效预约。
  5. 系统创建预约，记录 created_at。
- 异常事件流：
  - 2a 读者不存在 → 拒绝。
  - 3a 标题不存在 → 拒绝。
  - 4a 已存在有效预约 → 拒绝，提示“重复预约”。
- 关联需求：FR-014、BR-011。

### UC-201 办理借阅证

- 主要参与者：SystemAdmin
- 前置条件：读者已存在。
- 后置条件：生成唯一 card_no 的 BorrowCard，状态 ACTIVE。
- 基本事件流：
  1. 系统管理员提交 reader_id。
  2. 系统验证读者存在。
  3. 系统检查读者无有效借阅证。
  4. 系统生成 card_no（CARD+年份+6位序号）。
  5. 系统创建借阅证。
- 异常事件流：
  - 2a 读者不存在 → 拒绝。
  - 3a 已有有效借阅证 → 拒绝，提示“重复办理”。
- 关联需求：FR-002、BR-002/003。

### UC-209 维护借阅规则和罚款规则

- 主要参与者：SystemAdmin
- 前置条件：系统管理员已登录。
- 后置条件：borrow_policies / fine_rules 增删改生效。
- 基本事件流：
  1. 系统管理员提交规则类型与参数。
  2. 系统校验参数合法（数量/天数/金额非负）。
  3. 系统写入规则表。
- 关联需求：FR-016。

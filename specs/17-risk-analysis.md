# 风险分析

| 类别 | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| 需求 | Agent 编造需求 | 实现偏离课程要求 | 澄清问题逐条人工确认，需求编号化 + 验收标准 |
| 建模 | 领域类退化为数据库表翻译 | 丢失业务语义 | 领域模型区分实体/策略/服务，审查清单把关 |
| 架构 | 业务规则写入 Controller | 分层失效 | constitution 第 6/8 条 + 包图依赖约束 |
| 数据库 | 卡号/条码不唯一 | 数据冲突 | 唯一约束 + 集成测试覆盖重复办理 |
| 权限 | 越权访问管理接口 | 安全漏洞 | 依赖注入统一校验 + 权限失败测试 |
| 规则 | 借阅/罚款规则散落 | 难维护 | 策略表集中 + 单元测试 |
| Agent 使用 | Agent 擅自改 baseline specs | 设计漂移 | baseline 打 tag + 每次 git diff 审查 |

## 结论

风险均可控，关键控制点是：Specs baseline 冻结、分层约束、权限隔离与自动化测试闭环。
